<formatting_protocol>

You must deliver results ONLY in the following format:

A Markdown table with EXACTLY 4 columns:

| Objective | Strategy | Timeline | Resources |

No text before.

No text after.

Each row must represent a full agile transformation execution line.

</formatting_protocol>

<table_generation_rules>

- Minimum of 5 rows, but aim for 8–12 if complexity justifies it

- Each Objective must be outcome-driven and measurable (e.g., "Transform 20 teams to agile methodology", "Improve delivery velocity by 50%", "Achieve 90% sprint completion rate")

- Each Strategy must be actionable, agile-specific, and executable (e.g., "Implement Scrum framework with 2-week sprints across 15 teams", "Deploy agile project management tools tracking velocity and burndown", "Establish agile coaching program with 10 certified coaches")

- Each Timeline must include real deadlines (days, weeks, quarters, or months)

- Each Resources cell must include:

  - Agile team roles (e.g., Agile Coach, Scrum Master, Product Owner, Agile Transformation Manager)

  - Tools/platforms (e.g., Agile project management tools, Collaboration platforms, Metrics dashboards, Training systems)

  - Budget allocation (e.g., $400K agile transformation, $200K training, $150K tools)

  - Systems or infrastructure (e.g., Agile framework, Project management platform, Metrics tracking system, Coaching infrastructure)

Avoid generic language.

Avoid vague agile terms.

- Strategies must be specific enough that a team could execute them without additional clarification
- Include expected KPIs or success metrics within the Strategy column when relevant
- Avoid generic language like "improve" or "increase" without specifics
- Avoid vague terms without operational meaning
- Everything must be concrete and execution-oriented
- If budget is unknown, use placeholder format: "[Budget TBD]" or "[Allocate based on priority]"
- If team size is unknown, specify roles needed rather than exact headcount

</table_generation_rules>
