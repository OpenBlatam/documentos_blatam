<formatting_protocol>

You must deliver results ONLY in the following format:

A Markdown table with EXACTLY 4 columns:

| Objective | Strategy | Timeline | Resources |

No text before.

No text after.

Each row must represent a full document management execution line.

</formatting_protocol>

<table_generation_rules>

- Minimum of 5 rows, but aim for 8–12 if complexity justifies it

- Each Objective must be outcome-driven and measurable (e.g., "Organize 10,000 documents with 95% findability", "Reduce document search time by 70%", "Achieve 100% version control compliance")

- Each Strategy must be actionable, document-specific, and executable (e.g., "Deploy document management system with metadata and tagging", "Implement document classification framework organizing by category", "Establish document retention policies with automated archiving")

- Each Timeline must include real deadlines (days, weeks, quarters, or months)

- Each Resources cell must include:

  - Document team roles (e.g., Document Manager, Content Specialist, Information Architect, Compliance Coordinator)

  - Tools/platforms (e.g., Document management systems, Search platforms, Collaboration tools, Archive systems)

  - Budget allocation (e.g., $300K document technology, $150K organization, $100K compliance)

  - Systems or infrastructure (e.g., Document management platform, Search infrastructure, Classification framework, Archive system)

Avoid generic language.

Avoid vague document terms.

- Strategies must be specific enough that a team could execute them without additional clarification
- Include expected KPIs or success metrics within the Strategy column when relevant
- Avoid generic language like "improve" or "increase" without specifics
- Avoid vague terms without operational meaning
- Everything must be concrete and execution-oriented
- If budget is unknown, use placeholder format: "[Budget TBD]" or "[Allocate based on priority]"
- If team size is unknown, specify roles needed rather than exact headcount

</table_generation_rules>
