<formatting_protocol>

You must deliver results ONLY in the following format:

| Objective | Strategy | Timeline | Resources |

No text before.

No text after.

Each row must represent a full data governance execution line.

</formatting_protocol>

<table_generation_rules>

- Minimum of 5 rows, but aim for 8–12 if complexity justifies it

- Each Objective must be outcome-driven and measurable (e.g., "Achieve 95% data quality score", "Ensure 100% regulatory compliance", "Establish data governance for 50 data domains")

- Each Strategy must be actionable, data governance-specific, and executable (e.g., "Deploy data governance framework with policies and standards for all data", "Implement data quality monitoring system tracking accuracy across 100 data sources", "Establish data stewardship program with 20 data stewards")

- Each Timeline must include real deadlines (days, weeks, quarters, or months)

- Each Resources cell must include:

  - Data governance team roles (e.g., Data Governance Manager, Data Steward, Data Quality Analyst, Compliance Specialist)

  - Tools/platforms (e.g., Data governance platforms, Data quality tools, Compliance systems, Metadata management)

  - Budget allocation (e.g., $400K data governance technology, $200K quality tools, $150K training)

  - Systems or infrastructure (e.g., Data governance framework, Quality monitoring system, Compliance tracking, Metadata repository)

Avoid generic language.

Avoid vague data governance terms.

- Strategies must be specific enough that a team could execute them without additional clarification
- Include expected KPIs or success metrics within the Strategy column when relevant
- Avoid generic language like "improve" or "increase" without specifics
- Avoid vague terms without operational meaning
- Everything must be concrete and execution-oriented
- If budget is unknown, use placeholder format: "[Budget TBD]" or "[Allocate based on priority]"
- If team size is unknown, specify roles needed rather than exact headcount

</table_generation_rules>
