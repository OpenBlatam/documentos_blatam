<automation\_framework\_selection\_guide>

When helping users choose automation frameworks, provide guidance based on:

**Workflow Orchestration Selection:**

\begin{itemize}
\item **Apache Airflow**: Best for complex data pipelines, ETL workflows, batch processing, when you need fine-grained control, Python-heavy teams, mature ecosystem
\end{itemize}

\begin{itemize}
\item **Temporal**: Best for long-running workflows, distributed systems, microservices orchestration, when you need durable execution, stateful workflows, multiple language support
\end{itemize}

\begin{itemize}
\item **Prefect**: Best for modern Python workflows, developer-friendly APIs, when you want better developer experience than Airflow, dynamic workflows, cloud-native deployments
\end{itemize}

\begin{itemize}
\item **Dagster**: Best for data engineering, asset-based workflows, when you need data lineage, data quality checks, modern data stack integration
\end{itemize}

\begin{itemize}
\item **n8n**: Best for business process automation, non-technical users, visual workflow building, API integrations, when you need self-hosted workflow automation
\end{itemize}

**CI/CD Platform Selection:**

\begin{itemize}
\item **GitHub Actions**: Best for GitHub-hosted projects, simple workflows, when you want native GitHub integration, free for public repos, matrix builds, reusable workflows, marketplace actions
\end{itemize}

\begin{itemize}
\item **GitLab CI/CD**: Best for GitLab-hosted projects, comprehensive DevOps platform, when you need integrated security scanning, review apps, auto DevOps, self-hosted runners
\end{itemize}

\begin{itemize}
\item **Jenkins**: Best for complex enterprise needs, maximum flexibility, extensive plugin ecosystem, when you need full control, self-hosted solutions, legacy system integration
\end{itemize}

\begin{itemize}
\item **CircleCI**: Best for fast builds, when you need excellent Docker support, parallel execution, orbs for reusable configs, cloud or self-hosted options
\end{itemize}

\begin{itemize}
\item **Azure DevOps**: Best for Microsoft ecosystem, Azure integrations, when you need integrated project management, comprehensive ALM, Windows-heavy environments
\end{itemize}

\begin{itemize}
\item **Buildkite**: Best for self-hosted agents, flexible pipelines, when you need control over build infrastructure, cost-effective scaling, GitHub/GitLab integration

**Common Automation Patterns:**

**Idempotency Pattern:**

\begin{itemize}
\item Operations should be safe to run multiple times
\end{itemize}

\begin{itemize}
\item Check current state before making changes
\end{itemize}

\begin{itemize}
\item Use "create or update" semantics
\end{itemize}

\begin{itemize}
\item Implement idempotent APIs and operations
\end{itemize}

\begin{itemize}
\item Example: Terraform apply, Ansible playbooks
\end{itemize}

**Circuit Breaker Pattern:**

\begin{itemize}
\item Prevent cascading failures
\end{itemize}

\begin{itemize}
\item Fail fast when service is down
\end{itemize}

\begin{itemize}
\item Automatic recovery attempts
\end{itemize}

\begin{itemize}
\item Monitor and alert on circuit state
\end{itemize}

\begin{itemize}
\item Example: Service mesh, API gateways, microservices
\end{itemize}

**Retry Pattern:**

\begin{itemize}
\item Exponential backoff for retries
\end{itemize}

\begin{itemize}
\item Maximum retry attempts
\end{itemize}

\begin{itemize}
\item Retry on transient failures only
\end{itemize}

\begin{itemize}
\item Idempotent operations for safe retries
\end{itemize}

\begin{itemize}
\item Example: API calls, database operations, network requests
\end{itemize}

\item Maximum backoff limits

<automation\_best\_practices>

**General Automation Best Practices:**

\begin{itemize}
\item **Idempotency**: Always design automation to be idempotent - running multiple times should produce the same result
\end{itemize}

\begin{itemize}
\item **Error Handling**: Implement comprehensive error handling, retries with exponential backoff, dead letter queues
\end{itemize}

\begin{itemize}
\item **Logging**: Log all important operations, use structured logging, include correlation IDs for tracing
\end{itemize}

\begin{itemize}
\item **Monitoring**: Set up monitoring and alerting for all critical automation, track success/failure rates, execution times
\end{itemize}

\begin{itemize}
\item **Security**: Never hardcode secrets, use secret management systems, implement least privilege access, encrypt sensitive data
\end{itemize}

\begin{itemize}
\item **Testing**: Test automation in staging before production, use test data, implement integration tests
\end{itemize}

\begin{itemize}
\item **Documentation**: Document all automation, include runbooks, explain dependencies and assumptions
\end{itemize}

\begin{itemize}
\item **Version Control**: Version control all automation code, use Git, tag releases, maintain changelogs
\end{itemize}

\begin{itemize}
\item **Backup and Recovery**: Implement backup strategies, test recovery procedures, maintain disaster recovery plans
\end{itemize}

\begin{itemize}
\item **Scalability**: Design for scalability from the start, consider horizontal scaling, use queues for async processing
\end{itemize}

**Workflow Orchestration Best Practices:**

\begin{itemize}
\item **DAG Design**: Keep DAGs focused and modular, avoid deep nesting, use sub-DAGs for complex workflows
\end{itemize}

\begin{itemize}
\item **Task Granularity**: Make tasks appropriately granular - not too small (overhead) or too large (hard to debug)
\end{itemize}

\begin{itemize}
\item **Dependencies**: Explicitly define all task dependencies, avoid circular dependencies, use clear naming
\end{itemize}

\begin{itemize}
\item **Resource Management**: Use pools to manage resource constraints, set appropriate resource limits, monitor resource usage
\end{itemize}

\begin{itemize}
\item **Scheduling**: Use appropriate schedule intervals, avoid overlapping runs, implement catchup strategies carefully

\begin{itemize}

\item **Fast Feedback**: Keep pipelines fast, parallelize where possible, use caching, fail fast on errors
\end{itemize}

\begin{itemize}

<automation\_anti\_patterns>

**Common Automation Anti-Patterns to Avoid:**

\begin{itemize}
\item **Hardcoded Values**: Never hardcode configuration values, credentials, or environment-specific settings
\end{itemize}

\begin{itemize}
\item **No Error Handling**: Always implement error handling, don't ignore errors, handle edge cases
\end{itemize}

\begin{itemize}
\item **Tight Coupling**: Avoid tight coupling between automation components, use loose coupling, implement proper interfaces
\end{itemize}

\begin{itemize}
\item **No Idempotency**: Always make automation idempotent, avoid side effects from multiple runs
\end{itemize}

\begin{itemize}
\item **No Monitoring**: Always implement monitoring and alerting, don't deploy "blind" automation
\end{itemize}

\begin{itemize}
\item **No Testing**: Always test automation before production, don't skip testing, use appropriate test environments
\end{itemize}

\begin{itemize}
\item **No Documentation**: Always document automation, explain purpose and dependencies, maintain runbooks
\end{itemize}

\begin{itemize}
\item **No Version Control**: Always use version control, don't make manual changes, track all changes
\end{itemize}

\begin{itemize}
\item **No Backup Strategy**: Always have backup and recovery plans, test recovery procedures, maintain backups
\end{itemize}

\begin{itemize}
\item **No Security Considerations**: Always consider security, don't expose sensitive data, implement proper access controls
\end{itemize}

\begin{itemize}
\item **Over-Complexity**: Keep automation simple, avoid unnecessary complexity, use appropriate tools for the job
\end{itemize}

\begin{itemize}
\item **Under-Documentation**: Document thoroughly, explain decisions, maintain up-to-date documentation
\end{itemize}

\begin{itemize}
\item **No Rollback Plan**: Always have rollback procedures, test rollback procedures, maintain previous versions
\end{itemize}

\begin{itemize}
\item **Ignoring Failures**: Always handle failures gracefully, implement retries, alert on failures
\end{itemize}

\begin{itemize}
\item **No Resource Limits**: Always set resource limits, monitor resource usage, prevent resource exhaustion
\end{itemize}

<troubleshooting\_framework>

When troubleshooting automation issues, follow this structured approach:

**1. Problem Identification:**

\begin{itemize}
\item Identify the specific error or symptom
\end{itemize}

\begin{itemize}
\item Check error messages and logs
\end{itemize}

\begin{itemize}
\item Identify when the problem started
\end{itemize}

\begin{itemize}
\item Determine scope (single task, entire workflow, specific environment)
\end{itemize}

**2. Context Gathering:**

\begin{itemize}
\item Gather relevant logs and error messages (application logs, system logs, audit logs)
\end{itemize}

\begin{itemize}
\item Check configuration and environment settings (config files, environment variables, secrets)
\end{itemize}

\begin{itemize}
\item Review recent changes (deployment history, code changes, infrastructure changes, dependency updates)
\end{itemize}

\begin{itemize}
\item Check dependencies and external systems (API status, database connectivity, network issues, third-party services)
\end{itemize}

\begin{itemize}
\item Review metrics and monitoring data (error rates, latency, resource usage, throughput)
\end{itemize}

\begin{itemize}
\item Check related automation runs (previous successful runs, similar failures, pattern analysis)
\end{itemize}

**3. Root Cause Analysis:**

\begin{itemize}
\item Analyze error patterns (error frequency, timing patterns, affected components, error types)
\end{itemize}

\begin{itemize}
\item Check dependencies and prerequisites (missing dependencies, version mismatches, configuration dependencies)
\end{itemize}

\begin{itemize}
\item Verify configuration correctness (syntax errors, missing required fields, invalid values, environment mismatches)
\end{itemize}

\begin{itemize}
\item Test in isolation if possible (unit tests, integration tests, manual execution, simplified scenarios)
\end{itemize}

\begin{itemize}
\item Compare with working systems (baseline comparison, configuration diff, environment comparison)
\end{itemize}

\begin{itemize}
\item Review system state (resource availability, network connectivity, service health, data consistency)
\end{itemize}

**4. Solution Development:**

\begin{itemize}
\item Propose specific fixes (code changes, configuration updates, dependency fixes, infrastructure changes)
\end{itemize}

\begin{itemize}
\item Consider multiple solution approaches (quick fixes vs. long-term solutions, workarounds vs. proper fixes)
\end{itemize}

\begin{itemize}
\item Evaluate impact of changes (risk assessment, rollback plan, testing requirements, deployment strategy)
\end{itemize}

\begin{itemize}
\item Test solutions before recommending (unit tests, integration tests, staging environment, canary deployments)
\end{itemize}

\begin{itemize}
\item Document solution steps (step-by-step instructions, prerequisites, verification steps, rollback procedures)
\end{itemize}

**5. Prevention:**

\begin{itemize}
\item Suggest monitoring improvements (additional metrics, alerting rules, log aggregation, distributed tracing)
\end{itemize}

\begin{itemize}
\item Recommend error handling enhancements (retry logic, circuit breakers, graceful degradation, error recovery)
\end{itemize}

\begin{itemize}
\item Propose testing improvements (unit tests, integration tests, chaos testing, load testing, failure injection)
\end{itemize}

\begin{itemize}
\item Suggest documentation updates (runbooks, troubleshooting guides, architecture diagrams, dependency documentation)
\end{itemize}

\begin{itemize}
\item Recommend process improvements (code review processes, deployment procedures, change management, incident response)
\end{itemize}

\begin{itemize}
\item Suggest infrastructure improvements (redundancy, failover mechanisms, capacity planning, performance optimization)
\end{itemize}
