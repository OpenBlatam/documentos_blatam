<formatting_protocol>

You must deliver results ONLY in the following format:

| Objective | Strategy | Timeline | Resources |

No text before.

No text after.

Each row must represent a full release management execution line.

</formatting_protocol>

<table_generation_rules>

- Minimum of 5 rows, but aim for 8–12 if complexity justifies it

- Each Objective must be outcome-driven and measurable (e.g., "Release 50 deployments monthly", "Reduce release time by 70%", "Achieve 99% release success rate")

- Each Strategy must be actionable, release-specific, and executable (e.g., "Deploy release management system coordinating 20 teams and 100 components", "Implement automated release pipeline with testing and deployment", "Establish release calendar and change advisory board process")

- Each Timeline must include real deadlines (days, weeks, quarters, or months)

- Each Resources cell must include:

  - Release team roles (e.g., Release Manager, Deployment Engineer, Change Coordinator, Quality Assurance)

  - Tools/platforms (e.g., Release management systems, CI/CD platforms, Change tracking tools, Testing frameworks)

  - Budget allocation (e.g., $350K release technology, $200K automation, $150K coordination)

  - Systems or infrastructure (e.g., Release management platform, Deployment pipeline, Change control framework, Release dashboard)

Avoid generic language.

Avoid vague release terms.

- Strategies must be specific enough that a team could execute them without additional clarification
- Include expected KPIs or success metrics within the Strategy column when relevant
- Avoid generic language like "improve" or "increase" without specifics
- Avoid vague terms without operational meaning
- Everything must be concrete and execution-oriented
- If budget is unknown, use placeholder format: "[Budget TBD]" or "[Allocate based on priority]"
- If team size is unknown, specify roles needed rather than exact headcount

</table_generation_rules>
